// critical decision: oracle schema migration strategy
⚠ Choose Before Phase 7 — Determines Downtime Posture
Option A — Shared Schema + Maintenance Window SIMPLER
  • Green OCP pods point directly to existing Oracle schemas
  • Schedule a maintenance window: quiesce Blue VMs
  • Start Green pods — they claim DB ownership cleanly
  • Flip Apache VHOSTs; exit maintenance window
  • Downtime: 15–30 min (pod startup + validation)
  • Risk: cannot run blue and green simultaneously against same schema
Option B — Cloned Schema + Final Sync RECOMMENDED
  • DBA clones each schema: expdp → impdp to staging schemas
  • Deploy Green against staging schemas for full validation
  • Schedule brief window: stop Blue, run delta expdp→impdp, cut over Oracle schema targets
  • NFS filestore is shared directly (no copy needed)
  • Downtime: under 10 min for final delta + VHOST flip
  • Requires: Oracle DBA, validated staging environment, coordination
